# Процесс разработки

## Одна задача

1. Создать карточку по `templates/TASK.md`.
2. Зафиксировать текущее поведение и критерии приёмки.
3. Найти связанные файлы и данные.
4. Сделать минимальное изменение.
5. Добавить или обновить проверки.
6. Запустить статические проверки и ручной сценарий.
7. Обновить документацию и журнал.
8. При необходимости собрать новый релиз.

## Ветки и коммиты

Если Git настроен:

- одна задача — одна ветка;
- не смешивать рефакторинг и функциональное изменение без причины;
- сообщения: `fix: ...`, `feat: ...`, `docs: ...`, `security: ...`, `release: ...`;
- перед коммитом проверить отсутствие `config.php`, дампов, backup, логов и загруженных пользователем файлов.

Claude не должен выполнять push, merge, удаление веток или публикацию без прямой команды владельца.

## Комментарии в коде

Комментировать причину, ограничение безопасности и неочевидный поток данных. Не пересказывать очевидную строку. При изменении сложной логики обновлять существующий комментарий, чтобы он не лгал.

## Рефакторинг

Допустим отдельно от исправления поведения. Приоритеты: развернуть чрезмерно сжатые PHP/JS-файлы, вынести общие заголовки админки, аудит и операции координат, убрать два параллельных механизма поиска таблицы, сократить дубли CSS.
