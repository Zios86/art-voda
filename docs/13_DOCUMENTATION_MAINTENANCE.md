# Постоянное ведение документации

Владелец проекта поручил продолжать вести документацию после каждой доработки. Это обязательная часть готовности задачи.

## Что обновлять всегда

- `PROJECT_STATUS.md` — что сейчас работает, что не проверено и что блокирует выпуск;
- `CHANGELOG.md` — дата и понятное описание результата;
- QA-отчёт — какие автоматические и ручные проверки выполнены.

## Что обновлять по типу изменения

| Изменение | Документы |
|---|---|
| Новый, удалённый или перемещённый файл | `docs/03_FILE_MAP.md` |
| Новый модуль или изменение потока данных | `docs/02_ARCHITECTURE.md` |
| Таблица, поле, индекс или миграция | `docs/05_DATABASE_AND_MIGRATIONS.md` |
| Авторизация, CSRF, CSP, загрузка, удаление | `docs/06_SECURITY.md` |
| Новый тест или новый обязательный сценарий | `docs/07_TESTING_AND_QA.md` |
| Изменение Open Server | `docs/08_LOCAL_WINDOWS.md` |
| Состав ZIP или порядок Timeweb | `docs/09_RELEASE_AND_DEPLOYMENT.md` |
| Исправленная или новая проблема | `docs/10_BACKLOG.md` |
| Новое решение владельца | `docs/11_DECISIONS.md` |
| Новое постоянное правило для Claude | `CLAUDE.md` |

## Как вести статус задачи

У каждого пункта использовать одно из состояний:

- `Запланировано` — согласовано, работа не начата;
- `В работе` — есть незавершённые изменения;
- `Реализовано, не проверено` — код готов, но нужное окружение недоступно;
- `Проверено локально` — пройден Open Server;
- `Проверено на тестовом Timeweb`;
- `Опубликовано` — только после подтверждённой рабочей публикации;
- `Отложено` — владелец решил не выполнять сейчас.

Нельзя превращать «реализовано» в «проверено» только потому, что файл существует или проходит синтаксическую проверку.

## Запись после каждой задачи

```text
Дата и версия:
Задача:
Изменено:
Затронутые файлы:
Миграция:
Проверено:
Не проверено:
Известные ограничения:
Способ отката:
```

## Защита от устаревания

В начале нового чата Claude сверяет карту с реальными файлами. Если код и документация расходятся, он сообщает об этом и исправляет документацию в составе текущей задачи. Старое описание не удаляется бесследно, если оно объясняет важное решение: его переносят в changelog или журнал решений.
