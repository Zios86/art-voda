# Безопасность

## Обязательные меры

- сессионные cookie: `HttpOnly`, `Secure` на HTTPS, подходящий `SameSite`;
- смена session ID после входа без создания ложных активных сессий;
- rate limit основного входа и повторного подтверждения пароля;
- CSRF для каждого изменяющего запроса;
- проверка метода HTTP, ролей и входных типов;
- HTML-экранирование при выводе;
- подготовленные SQL-запросы;
- строгая CSP без inline-обработчиков;
- HSTS только в корректно настроенном HTTPS-окружении;
- журнал важных действий без секретов.

## Опасные операции

Импорт, восстановление, массовое удаление и массовая правка требуют: свежей сессии, CSRF, повторного пароля с rate limit, понятного предпросмотра последствий, backup и записи аудита.

## Фотографии

Проверять MIME по содержимому, допустимый формат, байты, размеры и число пикселей до полного декодирования. Создавать новое имя, пересохранять изображение, удалять метаданные. Не удалять файл, пока он упоминается текущей записью, историей или backup. Лучше перемещать в закрытую корзину на 30 дней.

## Уведомления

Одинаковое событие должно иметь cooldown, чтобы злоумышленник не мог исчерпать почтовый лимит. `mail()` не подтверждает доставку; важные обращения сохраняются локально с состоянием отправки.

## Проверка секретов перед релизом

```bash
rg -n "BEGIN (RSA|OPENSSH|PRIVATE)|password\s*=|api[_-]?key|secret\s*=|ADMIN_PASSWORD_HASH" .
```

Каждое совпадение проверить вручную. Безопасный placeholder не является утечкой.
