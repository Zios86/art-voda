# Текущее состояние проекта

Дата документа: 26 августа 2026 года. Основа: релиз v17, проведённый аудит и фактический состав архива. После каждой доработки Claude обязан сверять статус с исходниками.

## Последняя известная версия

- Релиз: `kioskvody_timeweb_2026-08-16_v17_admin_suite.zip`.
- Предыдущая миграция: `private/migrate_v15_to_v16.sql`.
- Чистая установка должна использовать `private/schema.sql`; старые миграции поверх чистой базы не запускаются.
- Полноценный запуск PHP/MySQL/Apache последней версии не был подтверждён.
- Статус: **не публиковать на рабочий сайт до устранения блокеров и smoke-теста**.
- Репозиторий исходников: `https://github.com/Zios86/art-voda`.
- GitHub используется для хранения кода и истории. GitHub Pages не является средой проверки PHP/MySQL.

## Реализовано в v17

- публичный сайт и карта автоматов;
- админ-панель;
- двухшаговый импорт CSV с предпросмотром;
- история карточек и откат;
- поиск дублей и контроль качества данных;
- расширенный поиск;
- массовая карта и пакетные операции;
- галерея и редактор фотографий;
- черновик формы в браузере;
- создание похожей карточки;
- предпросмотр и горячие клавиши;
- резервные копии, сравнение и восстановление;
- повторный пароль для опасных действий;
- список активных сессий;
- уведомления о подозрительных событиях;
- диагностика сервера.

2FA намеренно не реализована по решению владельца.

## Блокеры перед публикацией

1. Синхронизировать версии CSS/JS между `offline.html` и `sw.js`.
2. Удалить inline-обработчики `onsubmit`, которые блокируются CSP; перенести подтверждения во внешний JS.
3. Не удалять фотографии, если они используются историей карточек или резервной копией. Предпочтительна корзина с задержкой удаления.
4. В пакетной карте сохранять историю только для реально изменённых координат.
5. Ограничить частоту одинаковых писем о заблокированном входе.
6. Добавить отдельный rate limit для повторного ввода пароля.
7. Провести smoke-тест на Windows/Open Server и затем на тестовом поддомене Timeweb.

## Следующий приоритет

- исправить потерю черновика при неудачном сохранении;
- после восстановления черновика обновлять карту и предпросмотр;
- не дублировать активную сессию при смене PHP session ID;
- отклонять повторяющиеся номера внутри CSV;
- проверять существование фотографии при импорте;
- полностью журналировать импорт и восстановление;
- включать фотографии в резервное копирование или документировать отдельный backup;
- сортировать backup по реальной дате;
- сохранять обращения в БД/очереди, а не полагаться только на `mail()`;
- ограничить размер/пиксели фото до декодирования;
- расширить диагностику: `mbstring`, `pdo_mysql`, memory limit, место на диске, конфигурация и тест почты.
