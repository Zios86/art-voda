# AGENTS.md — инструкция для AI-агентов (ChatGPT, Codex и др.)

> Этот файл читается автоматически агентами OpenAI (ChatGPT с функцией агентов, Codex).
> Аналог: `CLAUDE.md` — для Claude / Anthropic.

## Проект

**Киосквода** — сайт сети киосков артезианской воды.
Стек: PHP 8.4, MySQL 8.0, Vanilla JS, Apache, без фреймворков.
Хостинг: Timeweb (Linux). Локальная разработка: Windows + Open Server Panel.

## Актуальность

Этот файл **всегда поддерживается в актуальном состоянии**: при любом изменении кода, структуры, версий или правил проекта `AGENTS.md` обновляется одновременно с остальной документацией. Если вы видите расхождение — сообщите владельцу.

## С чего начинать

Читай в указанном порядке:

1. `AGENTS.md` (этот файл)
2. `PROJECT_STATUS.md` — текущее состояние, что сделано, что заблокировано
3. `docs/00_START_HERE.md` — краткий маршрут по документации
4. `docs/02_ARCHITECTURE.md` — структура и технические решения
5. Только документы, относящиеся к текущей задаче

После чтения проверь реальную структуру файлов. Документация может отставать от кода.

## Жёсткие ограничения — нельзя нарушать

- Не добавлять статусы автоматов, даты обслуживания, способы оплаты на публичный сайт.
- Не придумывать номера, адреса, координаты, цены, фотографии, характеристики воды.
- Использовать только логотип из `public_html/img/brand-logo-artesian.*` — не генерировать новый.
- Не внедрять двухфакторную авторизацию без отдельного запроса владельца.
- Не менять публичные тексты и бизнес-логику за пределами поставленной задачи.
- Отвечать владельцу простым русским языком.

## Правила изменения кода

**До:**
1. Прочитай связанные файлы целиком.
2. Найди все места использования изменяемой функции, таблицы или поля.
3. Проверь незакоммиченные изменения — не затирай чужую работу.
4. Напиши короткий план и критерии готовности.

**Во время:**
- Делай минимальный связный патч.
- Совместимость: Windows, Open Server, Apache, PHP 8.4, MySQL 8.0.
- Используй подготовленные SQL-запросы (PDO), экранирование вывода, CSRF и проверку прав.
- Несколько изменений БД — оборачивай в транзакцию.
- Перед массовой операцией или восстановлением создавай резервную копию.
- Не редактируй архивы в `release/` вручную.
- Не добавляй секреты в репозиторий, логи, ответы или тестовые данные.

**После:**
1. Выполни проверки из `docs/07_TESTING_AND_QA.md`.
2. Обнови `PROJECT_STATUS.md` и `CHANGELOG.md`.
3. При изменении структуры — обнови `docs/03_FILE_MAP.md` и `docs/02_ARCHITECTURE.md`.
4. Релиз собирай только официальным скриптом по белому списку.

Документация — часть задачи. Нельзя говорить «готово», пока документы не обновлены.

## Безопасность

- Никогда не показывай `ADMIN_PASSWORD_HASH`, пароль БД, API-ключи, ключ аудита, почтовые настройки.
- Не читай и не выводи `private/config.php`. Для примеров используй только `private/config.php.example`.
- Любая изменяющая операция требует авторизации и CSRF-токена.
- Удаление, импорт, восстановление, массовая правка — повторный пароль + ограничение попыток.
- Загруженные изображения: проверять по содержимому, пересохранять, запрещать PHP в каталоге загрузок.
- Не ослаблять CSP. Встроенный JS переносить во внешние файлы.

## Работа с данными

- База данных — главный источник истины.
- `public_html/data/kiosks.json` — аварийный офлайн-файл, обновляется автоматически после изменения БД.
- Нельзя молча исправлять адреса и координаты — сначала показать владельцу список с источником.
- Импорт CSV: сначала только анализ, применение — отдельным подтверждённым действием.
- Дублирующий номер внутри одного CSV — ошибка, не правило «последняя строка победила».

## Критерии готовности задачи

Задача готова, только если:
- выполнены критерии владельца;
- нет новых предупреждений безопасности;
- протестированы успешный и ошибочный сценарии;
- документация отражает изменение;
- создан релиз и проверен состав ZIP (если просили выпуск);
- явно указано, что не удалось проверить локально.

## Формат ответа владельцу

Сначала — результат. Затем кратко:
- что изменено;
- что проверено;
- что осталось проверить на Open Server или Timeweb;
- где лежат файлы или архив;
- есть ли миграция и порядок её выполнения.

Не называть проект готовым к production без smoke-теста PHP/MySQL/Apache в браузере.

## Технические особенности

- **Шрифт:** Geist (woff2, кириллица + латиница), Inter как веб-fallback.
- **Токены бренда:** `--navy:#092f4a`, `--blue:#147ca8`, `--cyan:#41bde2`, `--sky:#eaf7fb`, `--sun:#f5bc3d`.
- **Шапка:** floating glass, `top:18px; border-radius:19px; backdrop-filter:blur(22px)`.
- **Сервис-воркер:** `kioskvoda-v15`, кеширует статику, не перехватывает `/admin/` и `/include/`.
- **Ближайшие киоски:** grid-bucketing O(n), ячейки ~25 м, проверка 3×3 соседей.
- **Карта:** Яндекс.Карты 2.1, API-ключ `53339f0b-...` (ограничить доменом в консоли разработчика).
- **Изображения:** `<picture>` с WebP-источником и PNG-fallback.
