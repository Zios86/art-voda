# AGENTS.md — правила для ChatGPT и Codex

Этот файл является аналогом `CLAUDE.md` для агентов OpenAI. Он обновляется одновременно с основной документацией проекта.

## Проект

«Киосквода» — сайт сети киосков артезианской воды.

- PHP 8.4;
- MySQL 8.0 или новее;
- Apache;
- Vanilla JavaScript;
- локальная разработка: Windows 10/11 и Open Server Panel;
- рабочий хостинг: Timeweb.

В инструкции Open Server выбран модуль MySQL 8.4. Это локальная конфигурация, а не требование использовать только эту минорную версию.

## Порядок начала работы

1. Прочитать `AGENTS.md`.
2. Прочитать `PROJECT_STATUS.md`.
3. Прочитать `docs/00_START_HERE.md` и `docs/02_ARCHITECTURE.md`.
4. Открыть только документы, относящиеся к задаче.
5. Сверить документацию с реальной структурой исходников.

## Ограничения владельца

- Не добавлять статусы автоматов.
- Не добавлять даты обслуживания.
- Не указывать способы оплаты.
- Не придумывать номера, адреса, координаты, цены, фотографии и характеристики воды.
- Не заменять настоящий логотип сгенерированным.
- Не внедрять 2FA без нового прямого запроса владельца.
- Не менять публичные тексты, дизайн и бизнес-логику за пределами задачи.
- Отвечать владельцу простым русским языком.

## Правила правок

До изменения:

1. Прочитать связанные файлы целиком.
2. Найти все места использования изменяемой функции, таблицы или поля.
3. Проверить незакоммиченные изменения и не затирать чужую работу.
4. Сформулировать короткий план и критерии готовности.

Во время изменения:

- делать минимальный связный патч;
- сохранять совместимость с Windows, Open Server, Apache, PHP 8.4 и MySQL 8.0+;
- использовать PDO, подготовленные SQL-запросы, экранирование вывода, CSRF и проверку прав;
- оборачивать связанные изменения БД в транзакцию;
- создавать резервную копию перед массовой операцией или восстановлением;
- не редактировать готовые релизные ZIP вручную;
- не добавлять секреты, логи, backup и пользовательские загрузки в Git.

После изменения:

1. Выполнить проверки из `docs/07_TESTING_AND_QA.md`.
2. Обновить `PROJECT_STATUS.md`, `CHANGELOG.md` и `AGENTS.md`.
3. При изменении структуры обновить `docs/03_FILE_MAP.md` и `docs/02_ARCHITECTURE.md`.
4. Явно указать, какие проверки не удалось выполнить на Open Server или Timeweb.

Документация является частью задачи. Нельзя сообщать «готово», если связанные документы не обновлены.

## Безопасность

- Не показывать пароль БД, хеш администратора, ключ аудита, почтовые настройки и API-ключи.
- Не читать и не выводить `private/config.php`; для примеров использовать только `private/config.php.example`.
- Изменяющие операции требуют авторизации и CSRF.
- Удаление, импорт, восстановление и массовая правка требуют повторного пароля и ограничения попыток.
- Проверять изображения по содержимому, пересохранять их и запрещать PHP в каталоге загрузок.
- Не ослаблять CSP; встроенный JavaScript переносить во внешние файлы.
- Клиентский ключ карты не копировать в документацию; ограничить его разрешёнными доменами у провайдера.

Текущее состояние v18-dev: rate limit повторного пароля, cooldown security-писем, корзина фотографий, проверка истории/backup, оценка памяти изображений и CI безопасности реализованы в исходниках, но ещё требуют smoke-теста Open Server и Timeweb.

## Работа с данными

- База данных — главный источник истины.
- `public_html/data/kiosks.json` — производный аварийный файл и должен обновляться после успешного изменения БД.
- Не исправлять адреса и координаты без подтверждения владельца и источника.
- CSV сначала анализировать, затем применять отдельным подтверждённым действием.
- Повторяющийся номер внутри одного CSV считать ошибкой.

## Критерии готовности

Задача готова, только если выполнены критерии владельца, проверены успешный и ошибочный сценарии, не ослаблена безопасность и обновлена документация. PHP/MySQL/Apache нельзя считать проверенными без реального запуска в браузере.

## Основные пути

- `public_html/` — web root;
- `public_html/index.php` — главная страница;
- `public_html/api/kiosks.php` — публичный API точек;
- `public_html/admin/` — административная панель;
- `public_html/include/` — общие PHP-модули;
- `public_html/data/kiosks.json` — аварийные данные;
- `public_html/sw.js` и `public_html/offline.html` — PWA и офлайн-режим;
- `private/schema.sql` — схема чистой установки;
- `private/config.php.example` — безопасный шаблон конфигурации;
- `private/config.php` — секреты, отсутствует в Git;
- `.github/` — автоматические проверки GitHub;
- `docs/` — проектная документация.
